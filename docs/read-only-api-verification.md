# ผลการตรวจสอบ API และฐานข้อมูลแบบไม่เปลี่ยนข้อมูล

**โครงการ:** Installment-payment  
**ขอบเขต:** ตรวจสอบเฉพาะ API, schema และการป้องกันสิทธิ์ โดยไม่มีคำสั่ง `INSERT`, `UPDATE` หรือ `DELETE` กับข้อมูลของผู้ใช้

## ผลการตรวจสอบ

| รายการ | วิธีทดสอบ | ผลลัพธ์ |
| --- | --- | --- |
| การป้องกันการอ่านข้อมูล Ledger | เรียก `GET /api/trpc/ledger.listParties` โดยไม่มี session | ระบบตอบ `401 Unauthorized` พร้อมรหัส `UNAUTHORIZED` และข้อความ `Please login (10001)` |
| สถานะ tRPC runtime | เรียก `GET /api/trpc/auth.me` โดยไม่มี session | ระบบตอบ `200 OK` สำหรับ endpoint สาธารณะ โดยไม่มีการเขียนข้อมูล |
| Validation และ authorization | รัน `pnpm check && pnpm test` | ผ่าน TypeScript และ Vitest ทั้ง 5 tests รวมถึงการปฏิเสธ anonymous access |
| Schema ฐานข้อมูล | อ่าน `information_schema.table_constraints` | พบ primary key, foreign key และ unique constraints สำหรับตาราง Ledger ครบ 16 รายการ |

## ความสัมพันธ์ที่ยืนยันแล้ว

ตาราง `ledger_parties`, `ledger_contracts`, `ledger_payment_schedules` และ `ledger_transactions` มี primary key ของตนเอง และเชื่อมกับเจ้าของข้อมูลใน `users` ผ่าน foreign key ทุกตาราง ตารางสัญญาเชื่อมกับคู่สัญญา ตารางงวดเชื่อมกับคู่สัญญาและสัญญา ส่วนธุรกรรมเชื่อมกับคู่สัญญา สัญญา และงวดชำระเมื่อเกี่ยวข้อง นอกจากนี้ยังมี unique constraints เพื่อป้องกันชื่อคู่สัญญาซ้ำในบทบาทเดียวกัน และป้องกันลำดับงวดซ้ำภายในสัญญาเดียวกัน

## ข้อจำกัดของการทดสอบครั้งนี้

การตรวจครั้งนี้ตั้งใจไม่ยืนยันตัวตนและไม่สร้างข้อมูล จึงยังไม่ได้ทดสอบเส้นทางที่ต้องเข้าสู่ระบบ ได้แก่ การสร้าง อ่าน แก้ไข และรีเฟรชข้อมูลของเจ้าของบัญชีจริง การทดสอบดังกล่าวควรดำเนินการเมื่อผู้ใช้อนุญาตให้เข้าสู่ระบบและยอมรับการสร้างข้อมูลทดสอบในบัญชีของตน
